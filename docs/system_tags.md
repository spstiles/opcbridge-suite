# System Tags

OPCBridge publishes built-in read-only diagnostics under the virtual connection
`_system`. These tags are generated by the runtime and are not stored in normal
tag JSON files.

System tags are visible in:

- SCADA Live Tags
- SCADA Workspace under `System`
- OPC UA under `Objects/System`
- Alarm source selection

System tags cannot be edited, deleted, imported, or exported as normal PLC tags.

## Bridge Tags

| Tag | Type | Meaning |
| --- | --- | --- |
| `System/Bridge/UptimeSeconds` | `int64` | OPCBridge process uptime. |
| `System/Bridge/Version` | `string` | OPCBridge component version. |
| `System/Bridge/ReloadActive` | `bool` | `true` while a runtime reload is requested or active. |
| `System/Bridge/ReloadGeneration` | `uint64` | Runtime reload/config generation counter. |

## Connection Tags

Each configured connection has diagnostics under:

```text
System/Connections/<friendly_connection_name>/
```

Virtual memory drivers and orphaned legacy tag stores are not reported as physical connections.

## Session Tags

SCADA and HMI expose the current browser's authenticated session under:

```text
System/Session/
```

Available tags are `LoggedIn`, `Username`, `FirstName`, `LastName`, `DisplayName`, `Groups`, and `IsAdmin`.
These values are browser-local so two operator stations can use different sessions without overwriting each other.

| Tag | Type | Meaning |
| --- | --- | --- |
| `Enabled` | `bool` | Connection is present in runtime config. |
| `TagCount` | `int32` | Enabled tag count for the connection. |
| `WithSnapshotCount` | `int32` | Tags with at least one runtime value snapshot. |
| `GoodCount` | `int32` | Tags with good quality snapshots. |
| `BadCount` | `int32` | Tags with bad quality snapshots. |
| `MissingCount` | `int32` | Enabled tags with no snapshot yet. |
| `BadHandleCount` | `int32` | Tags without a valid PLC handle/source. |
| `StalePercent` | `float64` | Percent of enabled tags currently bad, missing, or bad-handle. |
| `NewestAgeMs` | `int64` | Age of the newest tag snapshot in milliseconds, or `-1` if none. |
| `PollLanes` | `int32` | Configured polling lane count. |
| `ReadsTotal` | `uint64` | Total read attempts recorded by the poller. |
| `ReadsOk` | `uint64` | Successful read attempts. |
| `ReadsError` | `uint64` | Failed read attempts. |
| `ReadMsLast` | `float64` | Last read duration in milliseconds. |
| `ReadMsAvg` | `float64` | Average read duration in milliseconds. |

## OPC UA Sync Tags

These tags show the result of the last targeted runtime reload that attempted to
sync the live OPC UA namespace without a full OPC UA rebuild.

| Tag | Type | Meaning |
| --- | --- | --- |
| `System/OpcUa/Sync/LastAttempted` | `bool` | Last targeted reload attempted an OPC UA namespace sync. |
| `System/OpcUa/Sync/LastOk` | `bool` | Last targeted OPC UA sync completed without add failures. |
| `System/OpcUa/Sync/LastAdded` | `int32` | OPC UA nodes added during the last targeted sync. |
| `System/OpcUa/Sync/LastUpdated` | `int32` | Existing OPC UA bindings refreshed during the last targeted sync. |
| `System/OpcUa/Sync/LastRetired` | `int32` | Nodes marked unavailable because their tags were removed. |
| `System/OpcUa/Sync/LastDatatypeConflicts` | `int32` | Tags that need a full rebuild because their OPC UA datatype changed. |
| `System/OpcUa/Sync/LastAddFailures` | `int32` | Nodes that failed to add during the last targeted sync. |
| `System/OpcUa/Sync/FullRebuildRequired` | `bool` | `true` when a full OPC UA rebuild is still recommended. |
| `System/OpcUa/Sync/LastMessage` | `string` | Human-readable result from the last targeted sync. |

## Alarm Runtime Tags

OPCBridge reads alarm runtime status from `opcbridge-alarms` with a short timeout
and caches the result. If the alarm server is unavailable, `RuntimeConnected`
becomes `false` and counts fall back to safe defaults.

| Tag | Type | Meaning |
| --- | --- | --- |
| `System/Alarms/RuntimeConnected` | `bool` | Alarm runtime status API is reachable and healthy. |
| `System/Alarms/ActiveCount` | `int32` | Active alarm count. |
| `System/Alarms/UnackedCount` | `int32` | Unacknowledged alarm count. |
| `System/Alarms/ShelvedCount` | `int32` | Shelved alarm count. |
| `System/Alarms/DisabledCount` | `int32` | Disabled alarm count. |
| `System/Alarms/LastAlarmChangeAgeMs` | `int64` | Age of last alarm transition, or `-1` if none. |
| `System/Alarms/NotificationAttempts` | `uint64` | Notification attempt count. |
| `System/Alarms/NotificationSuccesses` | `uint64` | Successful notification attempt count. |
| `System/Alarms/NotificationFailures` | `uint64` | Failed notification attempt count. |
| `System/Alarms/LastNotificationAgeMs` | `int64` | Age of last notification attempt, or `-1` if none. |

## Data Logger Tags

OPCBridge reads data-logger runtime status from `opcbridge-logger` with a short
timeout and caches the result. If the logger service is unavailable,
`System/Logger/RuntimeConnected` becomes `false` and counts fall back to safe
defaults.

`System/Logger` is the canonical namespace. The former `System/Reporter`
paths are temporarily published as aliases with identical values so existing
alarms, HMI screens, logic, and external integrations continue to work while
their references are migrated.
Top-level data-logger tags:

| Tag | Type | Meaning |
| --- | --- | --- |
| `System/Logger/RuntimeConnected` | `bool` | Logger health API is reachable and healthy. |
| `System/Logger/DatabaseCount` | `int32` | Number of database monitor status rows reported by the logger service. |
| `System/Logger/DataCheckCount` | `int32` | Number of data-check status rows reported by the logger service. |

Database monitor tags are published under:

```text
System/Logger/Databases/<database_id>/
```

| Tag | Type | Meaning |
| --- | --- | --- |
| `Id` | `string` | Database ID. |
| `Enabled` | `bool` | Database monitor is enabled. |
| `Ok` | `bool` | Last monitor query succeeded. |
| `Running` | `bool` | Monitor query is currently running. |
| `LatencyMs` | `int64` | Last monitor query duration in milliseconds. |
| `ChecksTotal` | `uint64` | Total monitor checks run. |
| `FailuresTotal` | `uint64` | Total failed monitor checks. |
| `ConsecutiveFailures` | `int64` | Consecutive failed monitor checks. |
| `LastCheckAgeMs` | `int64` | Age of last monitor check, or `-1` if none. |
| `LastError` | `string` | Last monitor error text. |

Data-check tags are published under:

```text
System/Logger/DataChecks/<check_id>/
```

A data check runs a configured SQL query on a schedule. The first column of the
first row is used as the check value. Optional low/high thresholds set
`BelowLow`, `AboveHigh`, and `Ok`.

| Tag | Type | Meaning |
| --- | --- | --- |
| `Id` | `string` | Data-check ID. |
| `Enabled` | `bool` | Data check is enabled. |
| `Ok` | `bool` | Last run succeeded and was inside any configured thresholds. |
| `Running` | `bool` | Data check is currently running. |
| `BelowLow` | `bool` | Numeric value is below the configured low threshold. |
| `AboveHigh` | `bool` | Numeric value is above the configured high threshold. |
| `Value` | `string` | Raw first-column value from the query. |
| `NumericValue` | `float64` | Numeric version of `Value`, when it can be parsed. |
| `HasNumericValue` | `bool` | `true` when `Value` was parsed as a number. |
| `LatencyMs` | `int64` | Last query duration in milliseconds. |
| `RunsTotal` | `uint64` | Total data-check runs. |
| `FailuresTotal` | `uint64` | Runs that failed or violated thresholds. |
| `LastRunAgeMs` | `int64` | Age of last run, or `-1` if none. |
| `LastError` | `string` | Last error or threshold violation text. |

## Alarm Examples

Alarm when a PLC connection has too many stale/bad tags:

```text
connection_id: _system
tag_name: System/Connections/PLC01/StalePercent
type: high
threshold: 25
```

Alarm when the alarm runtime is unavailable:

```text
connection_id: _system
tag_name: System/Alarms/RuntimeConnected
type: equals
value: false
```

Alarm when host memory is high:

```text
connection_id: _system
tag_name: System/Host/MemoryUsedPercent
type: high
threshold: 90
```

Alarm when a database monitor fails:

```text
connection_id: _system
tag_name: System/Logger/Databases/main/Ok
type: equals
value: false
```

Alarm when a daily record-count data check is below its threshold:

```text
connection_id: _system
tag_name: System/Logger/DataChecks/daily_record_count/BelowLow
type: equals
value: true
```

### Alarm group and site summaries

The alarm runtime publishes read-only summary tags automatically for configured
alarm classification groups and sites, plus parents of slash-separated paths.
Notification routing/contact groups are separate and do not create these tags.
No HMI property or trigger type is required: select connection `_system` in the
existing tag picker, then browse `System/Alarms/Groups`.

For example, group `Field` and site `Lift Station 1` expose:

```text
System/Alarms/Groups/Field/Active
System/Alarms/Groups/Field/Lift Station 1/Active
```

Every group/site path exposes these leaves:

| Leaf | Type | Meaning |
| --- | --- | --- |
| `Active` | `bool` | At least one active alarm. |
| `Unacked` | `bool` | At least one previously active alarm still needs acknowledgment, including cleared alarms. |
| `ActiveUnacked` | `bool` | At least one alarm is active and unacknowledged. |
| `AllAcknowledged` | `bool` | No alarms in scope need acknowledgment; true for an empty group. |
| `ActiveCount` | `int32` | Number of active alarms. |
| `UnackedCount` | `int32` | Number needing acknowledgment, including cleared alarms. |
| `ActiveUnackedCount` | `int32` | Number active and unacknowledged. |
| `HighestActiveSeverity` | `int32` | Maximum numeric severity of active alarms, or zero when none. |

Parent summaries include all descendants, using `/` boundaries: `Field/Station 1`
does not include `Field/Station 10`. An alarm is counted once in each ancestor.
Disabled alarms, disabled sites, and currently shelved alarms do not contribute.
A newly configured alarm that has never activated does not need acknowledgment.
Defined empty groups/sites keep zero counts and false alarm conditions.
Use `ActiveUnacked` instead of `Unacked` when cleared alarms should not trigger an
indicator. Acknowledgment remains an operation on individual alarms; these tags
cannot acknowledge alarms or modify their state.

The core polls the alarm status API at most once every two seconds. Installed
services, HMI alarm panels, and HMI alarm summaries use the alarm endpoint in
**SCADA → Configure Server**: scheme, host, HTTP port (8085 by default), and
WebSocket port (8086 by default). The HMI has no separate alarm endpoint setting.
Saved changes are picked up without restarting the core; open HMI pages refresh
the endpoint within five seconds.

The installer sets `OPCBRIDGE_ALARM_SOURCE_CONFIG` on the core service and
`OPCBRIDGE_SCADA_CONFIG` on the HMI service to the installation's
`scada/config.json`. Standalone/core-only deployments without that configuration
retain the local `127.0.0.1:8085` default. Custom launchers should point both
variables at the same Configure Server JSON configuration. Existing HMI-local
alarm endpoint values are ignored; check Configure Server after upgrading.
If a previously readable source configuration becomes unavailable or invalid,
summary connectivity reports false rather than falling back to a different server.
Changing endpoints clears the previous server's cached group values. The configured
source applies to overall alarm counts and notification statistics as well as groups.

Summary tags are available through HTTP discovery/query, WebSocket system updates, read-only
OPC UA nodes, and system MQTT publication when enabled. New OPC UA variables are
created dynamically; removed group variables are removed without a server restart.
Clients that import OPC UA tags still need to browse/select new summary tags.

If the same alarm service is unavailable, the core retains its last group values and
sets `System/Alarms/RuntimeConnected` false. Gate indicators with that connectivity
tag to distinguish a retained value from a current summary. The pre-existing
overall `System/Alarms/UnackedCount` retains its active-only behavior; the new group
`UnackedCount` deliberately includes cleared, unacknowledged alarms.
